01 - Résumé système

Ce que fait la plateforme

Promptomatik aide des enseignants de langues à fabriquer des prompts pédagogiques structurés. L’utilisateur décrit un besoin, l’application lance une interview adaptative, assemble un prompt par blocs de techniques, puis permet de le sauvegarder, l’étudier, le modifier, le raffiner et le transformer en template.

Le produit ne génère pas directement les supports de cours. Il génère le prompt final que l’enseignant colle ensuite dans ChatGPT, Claude, Gemini, AI Studio ou un autre LLM.

Domaine central

Un prompt est stocké comme une suite ordonnée de blocs.

04 - Flux métier

Parcours principaux

Création d’un prompt

  • Minimum 20 caractères côté UI.
  • analyze extrait intention et champs manquants.
  • questions produit 2 à 5 questions ciblées.
  • assemble retourne soit un prompt, soit de nouvelles questions.
  • La sauvegarde crée une ligne prompts.

Vue et édition

  • User Mode concatène les contenus des blocs.
  • Study Mode ajoute badge technique et annotation.
  • Edit Mode permet contenu, ordre, ajout et suppression de blocs.
  • L’auto-save déclenche PUT /api/prompts/:id après 800 ms.

Raffinement

  • L’utilisateur choisit un problème et peut coller un extrait de sortie.
  • Le job refine relit les blocs actuels.
  • La revue montre added/modified/removed et les raisons.
  • Accept remplace blocs et tips du prompt.

Templates

  • Les templates sont des prompts avec is_template=1.
  • Le public ne voit que template_status='approved'.
  • Use clone le template vers l’utilisateur et garde template_id.
  • Les enseignants peuvent soumettre en communauté.

06 - Modèle de données

D1, JSON et relations

users

Email unique, hash mot de passe, rôle, langue préférée, profil JSON, is_active.

prompts

Nom, langue, tags JSON, blocs JSON, tips JSON, source_type, statut template, lien template original.

interview_jobs

Kind analyze/questions/assemble/refine, status, payload request/result, erreurs, timestamps.

invitations

Email invité, token unique, admin invitant, statut pending/accepted/expired, expiration 7 jours.

password_resets

Token reset unique, user_id, expiration 1 heure, used_at pour usage unique.

refinements

Table prévue pour tracer issue_type, description, sample_output et revised_prompt_id.

Les anciennes colonnes model_recommendation existent encore dans le schéma initial, mais la migration actuelle remplace l’usage produit par tips.
07 - Pipeline LLM

Interview asynchrone

01

Analyse

Extraction niveau, sujet, activité, audience, durée, source_type, missing_fields.

02

Questions

Options cliquables, multi-select, other, recommandé, normalisation de schéma.

03

Assemblage

Retour kind='prompt' ou kind='ask_user'.

04

Raffinement

Révision ciblée des blocs existants selon le problème signalé.

05

Polling

Le front attend completion via waitForInterviewJobResult.

06

Persist

Le résultat accepté met à jour prompts.blocks et tips.

Modèles

Par défaut anthropic/claude-sonnet-4.6, fallback moonshotai/kimi-k2.5, configurables via Wrangler.

Robustesse

Timeouts par étape, retries modèle, fallback, parsing JSON avec retrait des fences et extraction d’objet.

Langue

Language lock strict FR/EN/ES, contexte profil injecté uniquement si setup_completed.

08 - Sécurité et permissions

Contrôles en place

Sessions

KV avec TTL 7 jours, cookie HttpOnly, Secure, SameSite=Strict.

Ownership

Les routes prompts et jobs filtrent par user_id; les templates publics passent par le statut approuvé.

Admin

requireAdmin protège toutes les routes /api/admin/* et l’UI redirige les non-admins.

Comptes

Un utilisateur désactivé ne peut plus se connecter; l’admin ne peut pas se désactiver lui-même.

Secrets

OPENROUTER_API_KEY, RESEND_API_KEY et APP_SECRET restent des secrets Worker.

Reset

Les tokens expirent en 1 heure, sont consommés avec verrouillage SQL, et les anciens tokens sont invalidés.

09 - Dev, déploiement, fichiers

Repères d’exploitation

Scripts npm

  • npm run dev lance Vite avec plugin Cloudflare.
  • npm run build exécute tsc -b puis vite build.
  • npm run db:migrate applique les migrations D1 locales.
  • npm run deploy build puis wrangler deploy.

Configuration Worker

  • Assets SPA avec not_found_handling=single-page-application.
  • run_worker_first sur /api/*.
  • Queue consumer: batch 1, max retries 3, retry delay 5.
  • Compatibility date: 2026-02-10.
Carte des fichiers principaux

src/App.tsx: routes et protection. src/lib/api.ts: client API, timeouts, polling jobs. src/lib/hooks/use-interview.ts: machine d’état de l’interview. worker/index.ts: Hono et queue. worker/lib/interview-jobs.ts: jobs LLM. worker/lib/llm/prompts.ts: system prompts. migrations/*.sql: schéma D1. src/styles/tokens.css: design tokens.

Aucun script lint ou test explicite n’est déclaré dans package.json au moment de cette lecture; le gate vérifiable localement est donc principalement npm run build.
